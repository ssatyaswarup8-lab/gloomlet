# Gloomlet demo script (about 2 minutes)

Adapt the timing to the event format. Do not claim features work until you have tested them on the deployed site.

## 0:00–0:20 — Introduce Pip
“Meet Pip, a tiny Junior Dream Engineer. Gloomlet is a personal portfolio designed as a cozy dream world instead of a conventional list of projects.”

Show the hero, tagline, and the main navigation.

## 0:20–0:40 — Tell the story
“Visitors can explore Pip’s origin story through chapters, discovering the character and the world behind the projects.”

Navigate through a couple of story chapters.

## 0:40–1:00 — Explore projects
“These are the projects Pip has built. Each entry should make the purpose, technologies, and live/source links clear.”

Open one project or follow a working demo/source link.

## 1:00–1:20 — Explore the Dreamscape
“The Dreamscape turns navigation into a small journey. Visitors can select dream stops and track their progress.”

Select a stop and demonstrate progress. If completion is not reliable, show only the verified interaction.

## 1:20–1:40 — Make a lullaby
“The Lullaby Lab uses browser audio to create a small interactive sound experience, with mood and tempo controls.”

Start audio from the user gesture, change one control, and pause/mute it again.

## 1:40–2:00 — Invite participation and close
“Visitors can leave a note in the guestbook, and there’s a small secret for curious explorers. Gloomlet is about making a portfolio feel personal, playful, and worth exploring.”

Show the guestbook or Easter egg if tested. Finish on the hero or project section.

## Demo backup plan
- Have screenshots ready in case network or audio fails.
- Keep the deployed URL and repository URL handy.
- Do not enter secrets or personal credentials during the demo.
- If a feature fails, describe the limitation honestly and move on.
